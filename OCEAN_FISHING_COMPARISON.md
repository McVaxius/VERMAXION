# Ocean Fishing implementation comparison

VERMAXION owns the Ocean Fishing lifecycle directly, while the selected global provider controls in-duty fishing ownership. This records the supported scope and reliability behavior.

| Area | Current VERMAXION behavior |
|---|---|
| Character choice | Builds one queue per registration window: enabled `AlwaysFish` characters first, then enabled characters with XA Database Fisher levels ascending. XADB saved levels establish that cached order, but immediately before current-character preparation—and again after a relog—the coordinator reads native live Fisher level. An unavailable live read waits fail-closed; a normal character at or above the configured cap is rejected even if XADB is lower. Explicit `AlwaysFish` remains the only cap override. |
| Provider ownership | The global `VerMAXION + AutoHook` compatibility default keeps VERMAXION's existing in-duty baiting, movement, facing, casting, placement, and recovery, with AutoHook handling hook/reel behavior. `AutoHook AutoOceanFish` gives AutoHook every in-duty fishing action; VERMAXION still owns preparation, registration, result handling, cleanup, and return. The provider is snapshotted at run acquisition and cannot be changed while Fishing is active. |
| Fallback | A live at-cap mismatch, missing unlock, Fisher gearset, or usable lure excludes that character and advances immediately. A mismatch found after relog releases the owned lifecycle before advancing. ADS and travel failures retry the same character twice after 3 and 10 seconds. |
| Stop boundaries | No new attempt starts with less than 60 seconds remaining. Registration closure, queue confirmation, and any post-queue failure disable fallback. |
| External state | Provider changes and every run acquisition synchronize AutoHook's persisted `AutoOceanFish` setting through its reflected Boolean member and static `Save()`: off for `VerMAXION + AutoHook`, on for `AutoHook AutoOceanFish`. A missing or unwritable surface blocks startup. The AutoHook-owned provider enables AutoHook before relog/duty entry. The existing named YesAlready lease plus AutoRetainer multi-mode and AutoHook enabled-state snapshots remain lifecycle-owned and are restored through verified cleanup; the aligned `AutoOceanFish` setting is intentionally not restored. |
| Registration | Boarding and embark strings come from active-language `custom/006/CtsIkdEntrance_00663` rows 4 and 10. |
| Route selection | Selection is guarded by dialog index rather than localized route names. Indigo uses entry 0. Ruby uses entry 1 for Ruby Sea, Thavnair, and Unknown Island destinations. A missing requested entry falls back to entry 0. Legacy serialized Thavnair values normalize to Ruby and are hidden from global and per-character selectors. |
| Travel | Lifestream handles Limsa travel. Locked Arcanists' Guild shard 43 receives one navigation/attunement attempt, is verified before use, then falls back to direct Dryskthota navigation. |
| Boat positioning | With `VerMAXION + AutoHook`, VERMAXION samples continuously from the proven Henchman rails: starboard X 7.00–7.25 with Z -14–-4 or -2–5, and port X -7.25–-7.00 with Z -10–5.5; all use Y 6.711 and outward character rotations +1.5/-1.5. The starboard -4–-2 obstruction gap is never sampled. Up to 32 candidates are tested against live other-player positions with a 1.5-yalm minimum; player positions remain clearance inputs only. With `AutoHook AutoOceanFish`, VERMAXION performs no in-duty placement, movement, or facing. |
| Fishing sessions | With `VerMAXION + AutoHook`, Versatile Lure is set once at each seven-minute session start. Before the first valid acknowledgement, start dispatch and premature Fishing/Gathering conditions remain suppressed until the character is within 0.5 yalms, no other player is within 1.5 yalms, `vnavmesh.Path.IsRunning` has remained false for one continuous second, and outward character-facing readback is within 0.05 radians. Arrival stops vnavmesh and rotates the character, not the camera. Each eligible start sends `/ahstart` first and `/ac cast` second in the same tick as one attempt on the existing three-second cadence. After fishing first acknowledges, later interruptions and route changes retry the same pair in place without another placement gate. With `AutoHook AutoOceanFish`, VERMAXION performs no in-duty baiting or start/cast dispatch and only monitors bounded duty completion. AutoHook presets remain unmanaged. |
| Voyage movement boundary | With `VerMAXION + AutoHook`, navigation stall, 30-second timeout, false-`CanFish`, five unacknowledged paired starts, clearance loss, and facing timeout before acknowledgement select a fresh continuous point instead of cycling fixed indices. Each pair increments the attempt counter once. Recovery candidates stay at least 1.5 yalms from the prior point. An exhausted sampling pass stops navigation and retries once per second without casting. Recovery and settlement clocks reset or pause for route transitions, unavailable-player states, combat, casting, and occupied states. The first fully verified Fishing/Gathering acknowledgement permanently locks movement for the voyage; later interruptions remain in place. With `AutoHook AutoOceanFish`, VERMAXION performs no in-duty movement or recovery action. |
| Voyage completion | `DutyCompleted`, `IKDResult`, and disappearance of a previously observed duty context are accepted. Zone transitions and result settlement have bounded waits. |
| Inventory cleanup | Per-character opt-in `/ays discard`, followed by navigation near Limsa's Merchant & Mender and opt-in `/ays itemsell`. AutoRetainer must be readable and idle; cleanup warnings do not block return. |
| Return | A configured return is successful only after Lifestream activity settles or territory changes. It retries once after 30 seconds and fails after 120 seconds. |
| Deliberately excluded | Questionable integration, local/self repair, dynamic bait selection, and AutoHook preset management. ADS remains the only repair provider. |

Manual and AutoRetainer post-process triggers remain available. The disabled-by-default window watcher can invoke the same coordinator during an open startup window without waiting for an AutoRetainer post-process. Once a run starts, bounded recovery is automatic for that registration window and is not persisted.
